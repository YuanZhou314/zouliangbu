# 产品哲学（走两步）

> 一页纸，记结论。改动本文件 = 改产品方向，需先想清楚。

## 一句话

**记录是私有的，线路是公共的，社交是可选的。**

## 三层价值，只做前两层

| 层 | 内容 | 用户的具体问题 | 我们的投入 |
|---|---|---|---|
| 记录（私有） | 记录、回放、统计、对比、分享卡 | 「我走了哪」「这次怎么样」 | 80% |
| 线路（公共） | 线路库、离线包、"再走一次"、贡献提案 | 「去哪走」「别人怎么走的」 | 20% |
| 社交（可选） | 动态、关注、点赞 —— **不做** | 「被人看到」 | 0% |

理由：社交层的价值依赖用户密度；开源项目人少，运营成本还最高。
记录 + 线路不依赖用户量，「够用就好」。

## 三条判据（每个功能都要过一遍）

1. **需要别人参与吗？** 不需要 → 优先做；需要但不急 → 排后；需要很多人 → 别做。
2. **它是原料还是产品？** 原料（我的轨迹、第三方原始数据）→ 只能进提案通道；
   产品（公共线路）→ 直接可消费。混淆原料与产品 = UGC 路线失败的根因。
3. **断网了还剩什么？** 断网即归零 = 在服务"人"，不是服务"户外"。
   户外默认前提是**没信号**。

## 「我的轨迹」不止于统计

个人轨迹是**数据**不是**内容**：意义在拥有者手里，不在被围观。
所以优先把「我的」做**深**：

- 回放动画 + 照片 + 备注（把线变成一次旅行的回顾）
- **同一路段多次对比**（同一条线跑了 3 次，快了多少）→ 留存引擎
- 我的私藏线路册 + 一键"再走一次"（带上次轨迹与补给点出发）
- 把我的轨迹**贡献**进公共线路库（换署名，不换表演）
- 离线优先：记录、回放、导出全在本地

## 社区共维护：审核不是关卡，是升级通道

- **自动规则层**（机器判：重复检测、隐私点位、坐标合法性）→ 不可投票绕过
- **信号层**（认投票：客观修正达阈值且 0 反对 → 自动合并）→ 信任来自重复确认，不来自身份
- **升级通道**（机器判不了：外部导入合规、主观调整、隐私请求、争议）→ 才需要人
- **回滚层**（每次合并留快照，一键回退）→ 替代"防错"，改成"错了能低成本纠正"

不追求"永不出错"，追求"出错可快速恢复"。

## 内容治理的四类提交

| 类型 | 事实来源 | 需不需要人 | 流程 |
|---|---|---|---|
| A 自有轨迹上传 | 提交者本人 | 否 | 自动校验 → 直接上线 |
| B 既有线路勘误 | 亲历者 | 看信号 | 投票达阈值自动合并 / 争议才升级 |
| C 外部平台导入 | 第三方 | 是 | 人工**合规**审核（非事实审核） |
| D 主观调整（下架/评级） | 意见 | 是 | 人工 |

## 明确不做

用户动态/帖子流、关注/私信/粉丝数、点赞排行榜、必须登录才能记录、地图上手绘线路。

## 合规底线

- 代码开源（Apache/MIT）≠ 数据可自由分发。
- 社区原创内容 CC BY-SA；**导入的第三方数据**保留来源标注 + "版权归原作者，仅个人参考"。
- 详情页展示来源链接，方便用户回原平台核对。

## 失控信号（看到就要改回来）

- 首页开始像信息流，用户要往下划才能找到"记录"。
- 功能开始要求"有好友才有用"。
- 有人提议"加个审核页面/加个关注按钮"时，先对照上面判据。
