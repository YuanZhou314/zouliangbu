# 同路段对比（同一路线多次记录）

> 记录层做深的核心功能：不依赖社区规模，一个人用就有价值。
> 已实现核心算法：`app/src/main/java/com/zouliangbu/footprint/util/SegmentMatch.kt`（JVM 可测）。

## 为什么做

"这条线我跑了 3 次，这次比上次快了多少" —— 目前所有户外 App 都要用户自己肉眼比对。
这是留存引擎：让用户有理由**回来第二次**（见 docs/product-philosophy.md「我的轨迹不止于统计」）。

## 算法

纯几何，不依赖地图服务，离线可用：

1. 以 A 轨迹首点为原点做局部等距投影（1° 纬度 = 111320 m，经度按纬度余弦缩放）。
2. 每个 B 点投影到 A 折线：逐段求点到线段的最近点（参数 t 截断到 [0,1]）。
3. 距离 ≤ 容差（默认 30 m，与记录层精度规则同量级）的点记为命中；
   命中段内允许连续 2 个未命中点（抗 GPS 噪声/隧道失锁）。
4. 取最长命中段 → 在 A 上覆盖的弧长 = 共同路段长度。
5. 共同路段要同时满足：
   - 绝对长度 ≥ 200 m
   - 占较短一条的比例 ≥ 30%
   否则判定"不是同一条路"，不给出对比（避免两个路口就报"快了 12%"）。
6. 只在共同路段上算指标：A/B 各自的距离、时长、爬升、均速，以及距离比/时长比/爬升差。

## 输出

| 指标 | 含义 |
|---|---|
| distanceRatio | B 距离 / A 距离 |
| timeRatio | B 时长 / A 时长（>1 = 更慢） |
| ascentDeltaMeters | B 爬升 − A 爬升（正 = B 更累） |
| avgSpeedKmh | 共同路段均速 |

## 数据来源

只用本地 Room 里的轨迹（`TrackPoint` → `SegmentMatch.Sample`），不依赖服务端。
候选对比对象：同一条线路（线路 id 相同）或同区域、同名相近的历史轨迹。

## 待做

- UI：详情页"与上次对比"入口 → 选一条历史轨迹 → 展示差异卡片
- 反向匹配：A/B 互换时结果应对称（当前实现以 A 为基准折线，重合段取最长命中段，
  两条互为子集时结果可能不同，需要时改为双向取最长）
- 分段对比：把共同路段再按公里切段，逐段对比（复刻 Strava 的 splits 对比）
- 爬升口径与记录层统一（3 m 阈值），当前已一致

## 约束

- 两条轨迹必须同坐标系（App 内全链路 GCJ-02，不要在这里转换）。
- 采样间隔差异大时（A 5 秒/点，B 60 秒/点）结果仍然可用，命中率会下降，
  必要时按弧长重采样。
